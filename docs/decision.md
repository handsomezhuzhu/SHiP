## 为什么是 SHiP++

1. **贴合题目**：SHiP 的直系续作，五个 enhancement 全部围绕 SHCT/插入点/预取，
   报告可以自然地接着 SHiP 讲，不需要"硬拗"关系。
2. **风险最低**：核心结构（SHCT、R 位、采样组、RRPV）已经在本仓库实现并编译通过，
   剩下的是调参、实验、分析，而不是从零啃算法。
3. **实验设计清晰**：LRU / SRRIP / DRRIP / SHiP / SHiP++ 五条线，
   再做 5 个 enhancement 的消融，工作量与"一组 Benchmark 数据"的要求正好匹配。
4. **有明确的改进空间**：SHCT 压缩、训练信号、预取感知、多核共享，
   都能接 CacheFit(2026)/Harmony(2018) 的批评，符合"提出更好方法"的加分项。
5. **年份安全**：2017 年，距 2027-01 在十年内。

## 唯一的实质风险：CRC-2 是 workshop

CRC-2 是 ISCA 2017 的 co-located workshop，不是 ISCA 主会。
作业原文是"参考……各大会议……包括但不限于 ISCA、MICRO、HPCA……"，
严格按字面可能被卡。

**处理办法（本周内做）**：发一封邮件问助教/老师：
> "老师您好，我打算复现 SHiP++（The 2nd Cache Replacement Championship,
> co-located with ISCA 2017）……请问 workshop 论文是否算在'各大会议'范围内？"

- 如果答复 OK → 按 SHiP++ 推进。
- 如果答复不 OK → 换 **MPPPB（MICRO 2017）**：
  同属 SHiP 家族（感知机复用预测），顶会，13 页细节完整，无需离线训练，
  已有 ChampSim + trace + SHiP 系基线可复用，增量实现约 1–2 周。

## 为什么不选其他

- **Hawkeye（ISCA'16）**：论文质量最高、资料最全，但 2016 年 6 月距提交已超过十年，
  且 OPTgen + 采样器 + 预测器的实现量约为 SHiP++ 的 2 倍。可作为对照策略，不作为主复现。
- **Glider（MICRO'19）**：需要离线训练 LSTM、解释特征、再实现硬件 SVM；
  作者未放完整代码，两个月内失败风险高。
- **Mockingjay（HPCA'22）**：很好的"更近更强"选择，但长历史 + 多分类预测器实现复杂，
  适合作为"如果时间充裕"的备选。
- **RLR（HPCA'21）**：方法本身依赖离线 RL 训练，且不以签名预测为核心，跑题。
- **CARE（HPCA'23）**：并发感知的缓存管理框架，需要建模 MLP/预取，
  与"替换/插入策略"主线偏离。
- **SHiP 原文（MICRO'11）**：超出十年，只能当背景。

## "复现成功"的验收标准

- 三策略趋势合理：MPPPB 的几何平均 IPC 高于 SHiP 和 LRU（允许个别 workload 反向）；
- 相对幅度不要求等于原文 9.0%，但要能解释差异（SPEC2006→2017、MDPP→SRRIP、采样数、trace 长度）；
- 注意：原文主对比是 Hawkeye（+5.1%）和 Perceptron（+6.3%），SHiP 不在原文实验中；报告需说明；
- 至少 8 个 workload 的逐项数据 + 几何平均 + 消融；
- 有 1 个可量化的改进尝试（哪怕收益很小），并说明为什么。
