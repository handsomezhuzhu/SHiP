约束：作业要求"近十年"（2016 及以后）+ 复现算法 + 一组 Benchmark + Technical Report。

## 推荐排序

1. **SHiP++（首选）**：题目就是"SHiP 方向"，且在近十年内；核心改动是在 SHiP 的
   SHCT 上做增强，ChampSim 已有 `replacement/ship` 可直接改，**复现路径最短、风险最低**。
   实验可以做成：LRU / SRRIP / DRRIP / SHiP / SHiP++ 五条曲线，再分析偏差来源。
2. **Hawkeye（次选）**：影响力和引用量最大，资料最全；但需要实现 OPTgen + 采样器，
   代码量约为 SHiP++ 的 2 倍。若想"论文故事更完整"可选它。
3. **RLR（保底）**：实现简单，可与 SHiP 系做成本-收益对比；但"复现 SHiP 方向"的
   贴合度稍弱。

## 可预期的"不足与改进"切入点（写 Technical Report 用）

- **硬件开销**：SHiP++ 的 SHCT + 每行签名/反馈位约 20 KB；CacheFit (2026) 指出
  在先进工艺下这部分面积/静态功耗不可忽略。可尝试压缩签名位宽、共享 SHCT、
  或用小规模全局 PC 预测器替代 per-line 签名。
- **训练信号稀疏**：SHiP 系只在 hit/eviction 时更新计数器，反馈延迟大；
  可引入"访问时即更新"或期望命中数（Expected Hit Count）作为辅助监督。
- **预取污染**：SHiP 系不区分 demand/prefetch；Harmony/PACMan 已证明预取场景下
  需要特殊处理，可把"预取感知"作为改进点。
- **多核共享 LLC**：SHCT 按核复制还是共享、签名冲突、跨核干扰，都是可测的点。
- **Benchmark 代表性**：原文用 SPEC CPU2006；我们用 SPEC CPU2017（DPC-3 trace），
  可以分析两代 benchmark 下策略排序是否一致——这本身就是有价值的"偏差解释"。
